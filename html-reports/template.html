01

Recommendation

Recommend

Add a read-through Redis cache, scoped to product reads only.

It removes the p99 latency spike on the catalogue without touching write paths, and it is reversible in an afternoon. The cost is a new piece of infrastructure to operate — justified here, see risks.

The catalogue API serves reads that rarely change but are hit on every page load. We are paying database latency for data that is, in effect, static between deploys. Three options were weighed; only one is worth the operational cost.

02

Options weighed

ApproachLatency winEffortOperational costReversible
Read-through Redis pick High — cache hit ≈ 2 ms 2–3 days One new service Yes — feature-flagged
In-process LRU Medium — per-pod only 1 day None Yes
Materialised view in Postgres Medium 4–5 days Refresh job to own Hard — schema change

The ochre row is the recommended pick. Effort is calendar days for one engineer; latency is measured at p99.

03

How the read path changes

  1. Request arrives at the catalogue endpoint and we compute a stable cache key from the product id and locale.
  2. Check Redis. On a hit we return immediately — this is the 2 ms path that flattens the p99 spike.
  3. On a miss, read Postgres as today, then write the result back to Redis with a short TTL before responding.
  4. On deploy, a version prefix in the key invalidates everything at once — no manual flush.
Read-through, in full ~20 lines 
async function getProduct(id, locale) {
  const key = cacheKey(id, locale);
  const hit = await redis.get(key);
  if (hit) return JSON.parse(hit);   // 2ms path

  const row = await db.product(id, locale);
  await redis.set(key, JSON.stringify(row), 'EX', 300);
  return row;
}
const VERSION = process.env.DEPLOY_SHA;
export const cacheKey = (id, locale) =>
  `cat:${VERSION}:${locale}:${id}`;  // prefix invalidates on deploy
04

What this touches

Four files, one new dependency, zero write-path changes. The risk dots are the whole point of this block — read them first.

  • api/catalogue/handler.tsnew read-through branch
  • api/catalogue/key.tsnew file — key builder
  • infra/redis.tfnew service — needs review
  • config/flags.tscache_catalogue flag, default off
Note

Write paths are untouched, so correctness risk is bounded to “stale read for up to 300 s”, which the product team has already signed off.
