Pre-auth link for remote-surface

How a customer reaches the demo from a single smart-TV URL, end to end — JWT minting, TTL, and the tiny-URL hop that makes it typeable.

Date

Scope
impersonator → TinyURL → remote-surface

Raw ask Stage this … what do I do to test this and create an actual link, see it in the impersonator tool, how can it be used on the web. And remember the longer TTL. There's an option for tiny url … since our clients insert the URL into a smart TV, give them the shortest & simplest URL. Find out more on how this works.

The picture

The customer types one URL into a smart TV. Behind it: a JWT minted by the impersonator against a long-TTL AppClient record, optionally shortened by the MCE TinyURL service so nobody types 2 000 characters on a remote. The receiving app (remote-surface) detects ?auth_token=, hands the token to its platform shell, and proceeds as if SSO had happened. No login screen on the TV.

The flow — eight steps

01
Ops script

One-time per demo. Creates/updates a DynamoDB AppClient row.

Mint a long-TTL AppClient

Tokens minted later inherit record.expirySec from this row. The default for new AppClients is 3 hours — far too short for a demo. This script bumps it, preserving clientId/clientSecret if the row exists.

src/cloud/manual-scripts/dynamoDB/src/AppClients/setDemoAppClientTTL.ts
const existing = await getAppClientByIdentifiers(identifiers, logger);
if (existing) {
  await docClient.updateItem(logger, {
    TableName: config.tableName,
    Key: { id: existing.id },
    UpdateExpression: "SET expirySec = :expirySec",
    ExpressionAttributeValues: { ":expirySec": expirySec },
  });
  return;
}
await createAppClientRecord({ identifiers, expirySec }, false, logger);

05
YouTinyURL

Optional. Shorten the ~2 kB URL so it's typeable on a TV remote.

Shorten via TinyURL

Run it through tinyUrl.encodeUrl({ longUrl, expiryInSecs }) or the impersonator's "Tiny URL" target. How it works:

  • Encode — MD5-hashes the URL (first 8 hex), stores {keyUrl,url,expiry} in DDB, returns a /tinyurl/decode?keyUrl=… link.
  • Decode — unauthenticated GET, returns 302 to the original; query & fragment pass through.
  • TTL — capped by tinyUrl.maxTTLSeconds; DDB auto-deletes on expiry. Re-encoding is idempotent.
src/cloud/API/v5/src/TinyURL/src/encode/encode.ts:64
const hash = createHash("md5").update(longUrl).digest("hex").slice(0, config.hashLength);
await client.putItem(context.logger, {
  TableName: tableName,
  Item: { keyUrl: hash, url: longUrl, expiry: nowSec + effectiveExpirySeconds },
});
const shortUrl = `${tinyUrlDecodeBaseUrl}?keyUrl=${hash}`;
06
Smart TVTinyURL

Customer types the short URL; TinyURL 302s to the long one.

The TV follows the redirect

The decode endpoint reads keyUrl, returns 302 Location: <long-url>, the TV follows it transparently. This is where the JWT actually reaches the device — until now it lived only on your laptop and in the TinyURL row.

08
remote-surface

RelayClient connects with that JWT — display goes live.

RelayClient connects — display is live

getRelayAuthToken() pulls the token from the shell on every (re)connect; the Relay verifies signature and identifiers and joins the peer to its group. Pair the remote side with a second link targeting "Remote Surface (Remote)".

src/apps/cloud/remote-surface/src/services/transports/mce/auth.ts
export async function getRelayAuthToken(): Promise<string> {
  if (config.bypassAuth) return config.demoRelayToken;
  if (!window.mce) throw new Error("MCE platform shell not available");
  const { token } = await window.mce.jarvis.api.auth.getAuthToken().promise();
  return token;
}

URL anatomy

Without TinyURL — direct
https://remote-surface.dev-api.mce-sys.com/display?auth_token=eyJraWQ…≈1.5–2 kB…
≈ 2 000 characters. Unusable on a TV remote.
With TinyURL — recommended
https://api-v5.dev.mce-sys.com/tinyurl/decode?keyUrl=a3f9b2c1
≈ 60 characters. Typeable in under a minute.
Why not even shorter?

The resolver lives on the api-v5 domain, not a dedicated short host; a shorter alias domain (CloudFront → same Lambda) is separate work. Not blocking the demo — flag if the client pushes back.

TTL math & where it breaks

TTL math
  • JWT TTL — the AppClient's expirySec, capped at 10 days.
  • TinyURL TTL — independent; if shorter than the JWT, the short URL 404s first.
  • Effective lifetime = min(JWT, TinyURL) from issue.
  • Refresh — rerun the script; minted tokens keep their stamped TTL.
Where it goes wrong
  • 403 from TOKEN_OF_IDENTIFIERS — user lacks impersonateRegex.
  • Relay rejects the JWT — identifiers don't match the room.
  • Short URL 404s — TTL elapsed, or env-A hash resolved in env B.
  • TV can't reach the domain — RestrictAccessToMce WAF must be off.
